Vibe Coding 的循環

Vibe Coding 循環 — 7 步驟

  1. 設定目標 — 給 AI 清楚、細緻的概念與成功標準
  2. 任務拆解 — 把工作拆成清楚、可執行的步驟
  3. 開始對話 — 讓 AI 生成計畫或開始指令
  4. 仔細檢查 — 驗證方案正確性，建立信任之前先查
  5. 測試與驗證 — 用 TDD 精神驗證 AI 產出
  6. 改善與迭代 — 持續修正、直到達成目標
  7. 自動化工作流程 — 把整個循環自動化

實戰故事：Gene 的影片剪取工具

背景

  • Gene 花了 15 年在 YouTube 發現有趣內容就截圖
  • 累積了數千張截圖，但找回原始影片片段極費時
  • 決定用 vibe coding 一次解決這個問題

工具目標

輸入影片的截圖，自動剪出對應的影片片段，並把逐字稿燒錄到畫面上
  • 下載 YouTube 影片和逐字稿（使用 yt-dlp）
  • 用 FFmpeg 根據時間標記擷取指定片段
  • 從逐字稿擷取對應的文字內容
  • 把字幕燒錄到影片片段畫面上

任務一：影片擷取

提示詞：給我開始和結束時間（單位為秒），生成對應的 FFmpeg 指令，用來擷取影片片段，直接在 shell 執行，輸出存成 /tmp/output.mp4
  • 短短提示詞，效果良好
  • 不需查 FFmpeg 文件，不需理解命令參數
  • 幾分鐘內完成，Gene 決定直接往下走

任務二：處理逐字稿

  • 解析 JSON 字幕，找出對應時間範圍的文字
  • AI 生成 Clojure 函式，但其中一個測試失敗了
重要教訓：測試失敗的原因是測試本身有誤，而非程式碼

AI 並非永遠可靠，必須保持警覺、驗證答案。
AI 有時會長篇大論解釋自己為何正確，但結論可能是錯的。

任務三：生成字幕 1/2

  • 詢問 ChatGPT FFmpeg 支援的字幕格式（SRT 和 ASS）
  • 選擇 SRT 格式（位置較少、較容易實作）
  • 把逐字稿列表轉換成 SRT 檔
  • 修改 FFmpeg 指令，用 SRT caption 檔生成字幕影片

任務三：生成字幕 2/2

Gene 在打開影片看到附字幕的畫面瞬間呼喊：

「這真是扯到不可思議！」
  • 整個 vibe coding 合作不超過半小時
  • 提示詞也沒有幾個字，沒費多少腦力

成果 — 47 分鐘完成

  • ✅ 根據時間標記從 YouTube 影片擷取片段
  • ✅ 把逐字稿轉換成 SRT 格式字幕輸出
  • ✅ 用 FFmpeg 把字幕燒錄到影片片段
  • Gene 剪了 Erik Meijer 博士演講的 12 個精華片段發布
  • 累積約 2.5 萬次瀏覽
  • Erik Meijer 本人回覆：「Looking amazing. Feels much faster to grasp…」

沒有工具的副主廚就只能出一張嘴

實例：Steve 的 Puppeteer 故事

  • Steve 要在 app 裡加入幾個 UI 元素
  • 他只需描述問題——AI 自主選用 Puppeteer MCP 工具來控制瀏覽器
  • AI 截圖分析 UI，精準找到正確的 DOM select element
  • Steve 全程只描述問題，不需要自己動工具
沒有工具的副主廚就只能出一張嘴——工具讓 AI 從「顧問」變成「行動者」

AI 作為工具的統籌者

  • AI 承擔約 95% 的工作，透過整合的工具集完成任務
  • 你不需要懂每個工具的細節，只需描述目標
  • 挑一個主力 AI，再透過它呼叫其他工具
  • 工具本身不難，難的是整合與協調——讓 AI 來做這件事

程式設計代理的未來

展望未來，我們知道會有更多強大的工具出現：

  • 非同步、遠端代理：透過 GitHub Issues 或聊天介面指派任務，能在自己的容器中建立開發環境、使用工具、執行測試。包括 Claude Code 與 GitHub 的整合，還有 OpenAI Codex。
  • 代理叢集：同時使用複數 Claude Code 代理，但同時操作好幾個代理需要高度的專注力和警覺心。
  • 監督型代理：監督其他代理，有時指示代理進行變更，有時傳訊息給你，因為需要你的判斷。
  • 代理網格：協調代理合作的「社群」，用於解決更大規模的問題，包括軟體開發和業務流程運行。

9-5

Vibe Coding 實作精要

對話中，不需要太嚴格的限制

  • AI 出錯很常見，沒什麼大不了的 — 不要放棄對話，修改要求或調整方向，迭代才能活用 AI
  • AI 對於錯字和隨便的文法有無限的寬容 — 溝通不需要完美，專注解決問題即可
  • 盡量不花時間修正提示詞 — 重點在結果，不是完美的提示詞，逐步收斂到正確答案
  • 擁抱混亂而高效的解題對話架構 — 和 AI 合作像同事間的腦力激盪，不是在寫法律文件

讓錯誤自己發聲

  • 編譯錯誤 — 複製貼上編譯器的輸出
  • 執行錯誤 — 提供堆疊追蹤（stack trace）
  • 非預期行為／測試失敗 — 提供實際輸出和預期輸出
  • IDE 問題 — 提供相關的螢幕截圖
  • UI 問題 — 使用 Puppeteer 等螢幕擷取伺服器
與其說明問題，不如直接貼上錯誤訊息：
「Invalid Date: TypeError: date.format is not a function」

從模糊到精準：打磨你的要求

  • AI（還）沒辦法讀心——規格說明不夠清楚，往往帶來意外、困惑與挫折
  • 誠實告訴 AI 你知道什麼、想要什麼，不需擔心語句混亂或中途改變想法
  • 把口語內容複製給 AI，再補充你認為有幫助的額外資訊
以時區問題為例，AI 回傳：
· 使用 datetime 與 zoneinfo/pytz 函式庫  · 先將毫秒制時間轉為 UTC  · 建立時區轉換輔助函數
