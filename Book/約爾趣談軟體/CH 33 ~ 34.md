## 事情可沒那麼簡單

- 極限程式設計
    - ~~計畫和設計都是在浪費時間~~
- 匯入檔案功能
    - 用二頁式精靈程式
    - 第一頁 -> 你想從哪裡匯入檔案 ? 磁碟 or Web
    - 第二頁(Web) -> 輸入 URL
    - 第二頁(磁碟) -> 標準的檔案開啟對話框
    - ![](https://hackmd.io/_uploads/B1ZnTPBGT.png)
- 精靈程式不好做
    - 從網路匯入 Web 頁面 => 跳出 URL 對話框
    - 從磁碟匯入 Web 頁面 => 跳出檔案開啟對話框
- 複製檔案
    - 第一個參數式目錄怎搞?
    - 第二個參數是檔案怎搞?
    - 名稱重複怎搞?
    - 沒權限怎搞?
    - 複製到一半有問題怎搞?
    - ....
- 降低風險 
    - 尤其是時程風險最慘公司可能因此倒閉
    - ![](https://hackmd.io/_uploads/rkzdJuSMT.png)

- 事情可能沒那麼簡單 + 一定要降低風險 = 一定要在實作前進行設計
    - 改程式碼不像改文件簡單
- 結論
    - 一份看似簡單的規格，背後要考慮的細節從來都不簡單，這通常在開始開發就會慢慢發覺要預防的、要驗證的、流程應該怎麼設計等等，陸陸續續地發覺，有經驗的開發者，則可以用腦袋跑過一次，答出這些「延伸」細節
    - 其實就是基於「隨時隨地嘗試著降低風險」，而其中有一項需要避免的重大風險就是「進度風險」，也就是某件事情所花費的時間比預期多
    - 事情沒有像表面看起來那麼簡單，只會導出一個結論，「你必須先做設計再去實作」，且原則上「不要做無謂的設計」，漸進式的設計與實作是好的
